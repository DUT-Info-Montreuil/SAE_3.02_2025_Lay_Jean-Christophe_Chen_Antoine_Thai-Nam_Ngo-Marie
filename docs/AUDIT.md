# Rapport d'audit de sécurité — I-CONNECT

Périmètre : audit de sécurité de l'application PHP I-CONNECT (code et schéma de base issu d'un dump fourni). Chaque constat est vérifié en exécutant les scripts de `tests/securite/` sous PHP 8.3.6 : les contrôleurs tournent sur SQLite (pas de MySQL) et la sortie brute est conservée dans `docs/preuves_audit.txt` (exécution du 2026-10-09, `sh tests/securite/run_all.sh`, scripts du dépôt tels quels). « Type de preuve » : *exécuté* = le code de l'application tourne et son effet est observé ; *statique* = le test lit le code ou le schéma par motif, sans l'exécuter.

Statuts utilisés : **confirmée** (une ligne de sortie le montre), **non confirmée** (preuve insuffisante ou non tranchée), **faux positif** (le constat de l'IA est infirmé).

La colonne « Preuve observée » cite la ligne de sortie brute (`preuves_audit.txt:L`, L = numéro de ligne du fichier) et, quand le test en affiche une, la ligne `preuve :` associée. Auteur : découverte par Claude (IA) ; vérification humaine indiquée dans la colonne.

## Retour critique

1. Faux positifs et preuves faibles de l'IA : AUTH-2 (faux positif, la session est bien détruite ; le script de test l'affiche pourtant `[VULNÉRABLE]`), LM-2 (comportement peut-être voulu, non tranché), AUTH-8 (probabilité d'exploitation surestimée) et INJ-SQL-CFG (le test d'origine donne `[OK]` à tort ; la correction du script reste à faire dans `test_injections.php`). Plus de la moitié des « confirmées » de la première version étaient des analyses statiques ; UP-1 reste non confirmée faute d'écriture exécutée.
2. J'ai (Jean-Christophe Lay) relu le code des 12 constats du tableau. Écarts constatés : AUTH-8 (gravité corrigée), INJ-SQL-CFG (test à corriger), AUTH-2 (reclassé en faux positif), LM-2 (non tranché), UP-1 (rétrogradé en non confirmée). Les constats de la première version qui ne figurent pas dans ce tableau n'ont pas été relus par un humain et ne sont pas retenus.
3. Faille trouvée par moi : aucune. Toutes les failles ont été découvertes par Claude. Mon apport (Jean-Christophe Lay) : la relecture du code et la vérification des failles, et la demande de vérification qui a conduit l'IA à corriger les tests.
